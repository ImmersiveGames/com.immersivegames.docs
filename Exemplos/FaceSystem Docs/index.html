Technical Documentation

Face System Specification

Architecture and runtime behavior for the data-driven, atlas-based facial animation framework.

Architecture

The Face System is a data-driven, atlas-based facial animation framework. Runtime behavior is organized entirely by user-defined Track IDs.

FaceSpriteLibrary
        |
FaceState
        |
FaceAnimation
        |
FaceController
        |
Track Binding
        |
Renderer + Material Index

The runtime must not assume that tracks such as eyes or mouth exist. Projects can define any tracks required by their characters, including eyebrows, tears, accessories, or fx.

FaceSpriteLibrary

FaceSpriteLibrary contains a list of sprite tracks.

Each sprite track contains:

  • Unique Track ID
  • Atlas texture
  • Grid size
  • Sprite entries

Each sprite entry maps a Sprite ID to an atlas coordinate. Runtime lookups are dictionary-backed and deterministic.

FaceState

FaceState represents the persistent facial appearance and contains a list of Track States.

Each Track State contains:

  • Track ID
  • Default Frame ID
  • Semantic frame mappings

Each mapping connects a semantic Frame ID to a Sprite ID in the matching library track.

The Default Frame ID explicitly identifies the persistent frame. It resolves through the semantic mappings and is independent from list ordering. All mappings remain available to FromState animations.

States do not perform timing or playback.

FaceAnimation

FaceAnimation contains a dynamic list of Animation Tracks.

Each Animation Track contains:

  • Track ID
  • Enabled state
  • Frame source
  • Timed frames

FromState frames resolve semantic Frame IDs through the active FaceState. CustomLibrary frames resolve Sprite IDs through the animation's FaceSpriteLibrary.

Animations override only the Track IDs they contain. When an animation ends, the next update naturally restores the active state's base frame.

Playback modes:

  • Sequential
  • Loop
  • Interval
  • Random

FaceController

FaceController owns:

  • Registered states
  • Registered animations
  • Active state
  • Active animation players
  • Track bindings

Runtime order:

  1. Resolve each state's base track frame.
  2. Resolve active animation overrides.
  3. Apply the final frame for each Track ID to its binding.

Starting an animation stops existing animation playback only for matching Track IDs. There is no restore stack, animator graph, blend tree, or state graph.

Track Bindings

A Track Binding contains:

  • Track ID
  • Renderer
  • Material Index

Bindings support both MeshRenderer and SkinnedMeshRenderer through Unity's common Renderer API.

Atlas properties are applied with:

renderer.SetPropertyBlock(block, materialIndex);

This supports:

  • Separate renderers with material index 0
  • Multiple tracks on one shared renderer
  • Bone-driven meshes using SkinnedMeshRenderer

Material Properties

Face shaders must expose:

_Tiling
_Offset

The controller calculates:

Tiling X = 1 / Columns
Tiling Y = 1 / Rows

Offset X = Column / Columns
Offset Y = (Rows - 1 - Row) / Rows

Material instances must not be created at runtime. Updates use a cached MaterialPropertyBlock per binding.

Validation

Validation reports:

  • Empty or duplicate Track IDs
  • Missing atlas textures
  • Invalid grid sizes
  • Sprite coordinates outside the grid
  • Empty or duplicate Sprite IDs
  • Missing semantic Frame IDs
  • Empty Default Frame IDs
  • Default Frame IDs missing from their Track State mappings
  • Missing Sprite IDs
  • Missing library tracks
  • Missing renderers
  • Invalid material indices
  • Invalid animation durations

Missing data is not guessed and does not silently fall back to another track.

Transparency and Render Order

Transparent facial materials may be sorted differently from physical mesh depth. Explicit material Render Queue values can provide stable ordering:

Eyes Material  = 3000
Mouth Material = 3010

The correct order depends on the character. Render Queue ordering is often preferable to moving meshes solely to influence transparent sorting.

Shader Support

Available shader implementations:

  • URP: Assets/Shader/FaceAtlasShader.shadergraph
  • Built-in Render Pipeline: Assets/Shaders/FaceAtlasBuiltIn.shader

Built-in projects should use Face/Atlas Built-In instead of converting the project to URP.

User Guide

Face System User Manual

Asset setup, controller configuration, runtime API, and troubleshooting for Unity projects.

Introduction

The Face System is a lightweight atlas facial animation framework for Unity. It uses dynamic Track IDs rather than fixed facial parts.

Example Track IDs:

eyes
mouth
eyebrows
tears
fx

New tracks are created entirely through assets and inspector configuration. No runtime code changes are required.

Workflow

Atlas textures
    |
FaceSpriteLibrary tracks
    |
FaceState track states
    |
FaceAnimation tracks
    |
FaceController bindings
    |
Renderer material slots

Preparing Atlases

Each track uses a regular grid atlas. Every sprite must occupy one cell.

Tiling X = 1 / Columns
Tiling Y = 1 / Rows

Keep cells evenly sized and aligned. Separate tracks may use different atlas textures and grid sizes.

Creating a FaceSpriteLibrary

Create:

Create > Face System > Face Sprite Library

Add one entry to Tracks for every facial layer.

For each track configure:

  • Track ID
  • Atlas texture
  • Grid size
  • Sprite IDs and atlas coordinates

Example:

Track ID: eyebrows
Atlas: EyebrowExpressions
Grid Size: 4 x 2

eyebrow.normal -> (0, 0)
eyebrow.angry  -> (1, 0)
eyebrow.sad    -> (2, 0)

Track IDs and Sprite IDs are case-sensitive string contracts.

Creating FaceStates

Create:

Create > Face System > Face State

Assign the sprite library, then add Track States.

Each Track State contains:

  • Track ID matching a library track
  • Default Frame ID
  • Semantic Frame ID to Sprite ID mappings

Example:

Track ID: eyes

opened -> eye.normal.open
half   -> eye.normal.half
closed -> eye.normal.closed

Default Frame ID selects the persistent appearance for that track:

Default Frame ID: opened

It must match one of the semantic Frame IDs in the mapping list. Reordering the mappings does not change the resting appearance.

Creating FaceAnimations

Create:

Create > Face System > Face Animation

Add only the tracks the animation should override.

Each Animation Track contains:

  • Track ID
  • Enabled toggle
  • Frame Source
  • Timed frame list

FromState

FromState uses semantic Frame IDs from the current state.

Example blink:

Track ID: eyes

half
closed
half
opened

Assign a Template State for inspector validation. Runtime resolution always uses the controller's active state.

CustomLibrary

CustomLibrary references Sprite IDs directly from the animation's library. Use it for visuals that should ignore the current state, such as special FX or look-around frames.

Configuring FaceController

Add FaceController to the character and configure:

  • Track Bindings
  • States
  • Animations

Each Track Binding connects:

Track ID -> Renderer -> Material Index

Separate Meshes

eyes  -> EyesQuad Renderer  -> index 0
mouth -> MouthQuad Renderer -> index 0

Shared Renderer

A single MeshRenderer or SkinnedMeshRenderer can expose several materials:

0 Skin
1 Eyes
2 Mouth
3 Eyebrows

Bindings:

eyes     -> HeadRenderer -> index 1
mouth    -> HeadRenderer -> index 2
eyebrows -> HeadRenderer -> index 3

Material Index must exist in the renderer's material list.

MeshRenderer and SkinnedMeshRenderer

Bindings use Unity's common Renderer API and support:

  • MeshRenderer for static meshes
  • SkinnedMeshRenderer for rigged or bone-driven meshes

Both use the same indexed MaterialPropertyBlock runtime path.

Runtime API

Set the active state:

faceController.SetState("fs.angry.state");

Play an animation:

faceController.PlayAnimation("fa.blink");

Stop animation overrides for one dynamic track:

faceController.StopAnimation("eyes");

Stop all animations:

faceController.StopAllAnimations();

FaceControllerTester

Add FaceControllerTester beside the controller. In Play Mode its inspector creates buttons for registered states and animations.

Shader Setup

Shader options:

  • URP: Assets/Shader/FaceAtlasShader.shadergraph
  • Built-in Render Pipeline: Assets/Shaders/FaceAtlasBuiltIn.shader

Face materials must expose _Tiling and _Offset. The controller updates these properties through MaterialPropertyBlock.

Face Layering and Render Order

Transparent materials can render in an unexpected order when facial surfaces are close together.

Symptoms include:

  • Eyes rendering over the mouth
  • Mouth rendering over the eyes
  • Unstable layering between transparent tracks

Set explicit Render Queue values when needed:

Eyes Material  = 3000
Mouth Material = 3010

Higher values render later. Reverse the values when the desired layering is reversed. Exact values depend on the character.

Troubleshooting

A Track Does Not Render

Check:

  • Track ID matches across library, state, animation, and binding
  • Binding has a renderer
  • Material Index exists
  • Atlas grid size is valid
  • Sprite coordinate is inside the grid

An Animation Does Not Override a Track

Check:

  • Animation is registered in the controller
  • Animation Track is enabled
  • Track ID matches the state and binding
  • FromState Frame ID exists in the active state
  • CustomLibrary Sprite ID exists in the selected library

Wrong Base Frame Appears

Check that Default Frame ID points to the intended semantic mapping. The mapping order does not control the base frame.

V1 Migration

V2 intentionally removes the fixed Eyes/Mouth data model.

Migration mapping:

eyesAtlas + eyes entries   -> library track "eyes"
mouthAtlas + mouth entries -> library track "mouth"

FaceState.eyes  -> Track State "eyes"
FaceState.mouth -> Track State "mouth"

FaceAnimation.eyes  -> Animation Track "eyes"
FaceAnimation.mouth -> Animation Track "mouth"

eyesPart / mouthPart -> Track Bindings

FacePart is no longer used. Configure the renderer and material index directly in FaceController.

Existing V2 state assets created before explicit defaults are migrated by setting Default Frame ID to their previous first mapping, preserving their visual behavior.
