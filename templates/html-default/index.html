Overview

Introduction

The Immersive Games Documentation Framework defines a structured, offline-first approach for authoring and rendering project documentation.

Documentation Flow

The framework starts with authored Markdown and produces readable offline output through a Renderer.

  1. Authors and AI agents write structured Markdown.
  2. The Renderer consumes framework contracts.
  3. The Theme System styles semantic output.
  4. Users read a portable offline documentation package.

Note

HTML is the first output target, not the framework itself.

Decision

Decision: Markdown remains the source of truth.

Reason: Markdown is easy to edit, review, version, and render.

Status: Approved

Offline Package

The default template works locally without a server, CDN, remote fonts, or external JavaScript.

  • All stylesheets are local.
  • All scripts are local.
  • Required assets use relative paths.

Engineering

Architecture

Engineering documentation captures system structure, runtime behavior, API surfaces, and asset handling expectations.

Systems

Systems documentation should explain responsibilities, boundaries, and data flow without coupling the source content to visual layout.

Documentation represents knowledge first. Presentation is derivative.

Asset Handling

Risk

Glossary

Documentation Project

Glossary terms define project vocabulary using Markdown headings and standard links.

Document

Definition: The highest editorial unit inside a Documentation Project.

Related Terms: Component, Renderer

Component

Definition: A reusable semantic documentation structure with a defined purpose.

Aliases: Documentation component, semantic component

Renderer

Definition: An implementation that transforms a valid Documentation Project into an output format.
